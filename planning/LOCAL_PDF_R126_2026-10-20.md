# Local PDF form extraction — r126, 20 October 2026

Swift NAVFIT now reads the supported May 2025 NAVPERS EVAL, CHIEFEVAL and FITREP
form data directly inside Access. The released ACCDB does not need Acrobat,
Reader, Python, PowerShell, a PDF helper executable, or an internet connection
for extraction. Development fixture generators use pikepdf as an independent
oracle; that package is not distributed or invoked by the application.

## User workflow

Reports > Import reports > structured PDF retains Choose, Preview, Apply and
Results. The extraction check now tests the embedded reader. Its diagnostic
does not clear a prepared preview or merge. Existing field mapping remains
partial: 41 EVAL, 52 CHIEFEVAL and 37 FITREP mapping rows (including CommandEmployment). Blank source values never
erase saved values. Identifier choices, stale-target checks, recovery/approval
guards, duplicate protection, source hashes, retained XML, revisions and undo
remain in the existing importer.

## Implementation and bounds

- `modPDFLocal` follows the final cross-reference table/stream and `/Prev`
  chain, resolves compressed object streams, and reads the active catalog's
  XFA template/datasets references. Newer entries override earlier entries;
  freed objects are not resurrected from older revisions.
- `modPDFInflate` decodes bounded zlib/DEFLATE streams and verifies Adler-32.
  TIFF/PNG predictor support handles compressed cross-reference streams.
- `modPDFCrypto` uses Windows cryptography and the PDF Standard Security
  algorithms for R2–R4 forms that open with an empty user password and permit
  extraction. This includes the supplied AES-128 CHIEFEVAL form. Required
  passwords, prohibited extraction and unsupported encryption are rejected.
- Only the three exact reviewed raw template packet SHA-256 identities are
  accepted. Files are limited to 30 MB; decoded packets to 4 MB; aggregate
  decoded streams to 32 MB, with additional depth/token/object/revision limits.
- PDF/XFA scripts and actions are never evaluated. Strict UTF-8 decoding and
  MSXML with DTD/external resolution disabled validate the data XML.

The adapter receipt is `pdf-xfa-v3-local`, retaining the `pdf-xfa-v*` family used
by duplicate/undo services. The retained template hash now means SHA-256 of the
raw decoded template packet, rather than Acrobat's serialized XML string.
Historical receipts are preserved without rewriting their hashes. No database
schema change: app 0.26.1-dev, schema 26.

Scanned/flattened PDFs, generic AcroForms, single-packet XFA, unreviewed template
revisions, unsupported filters and unsupported encryption require manual entry.
Extraction does not establish signature authenticity or printed layout fidelity.

## Release assembly

The release uses scripts/build-local-pdf-update.ps1 on the verified r125 Blank.
It checks that every user-data table is empty and schema is 26, creates a new
file, refreshes changed modules and PDF wording, and verifies all 97 static
modules, four generated modules, identity, unload guards and bindings across 65
forms after reopening. The template hash remains unchanged. The adjacent build
receipt records this incremental assembly and its source fingerprints.

A full-generation attempt raised a closed-object error in the existing
report-tools validation-form pass. That incomplete candidate is retained under
build/ and was not released. This release does not claim a successful fresh
full-generation run. A separate hard-coded version in that generator now reads
the canonical version instead of resetting it to 0.26.0-dev.

## Reproduce focused checks

Generate fixtures with `scripts/make-local-pdf-fixtures.py --output <new-folder>`
using a development Python environment with pikepdf, then run
`scripts/test-local-pdf.ps1 -BuildPath <blank> -FixturePath <folder>`.
`-InstallReader` is for development testing against an older disposable copy.
The fixture generator refuses to overwrite a fixture directory.

The focused suite compares exact packet bytes against independent pikepdf
extraction; covers supplied forms, classic/stream xrefs, object streams,
linearized and incremental PDFs, stored/fixed/dynamic compression, supported
empty-password security, and rejected malformed/unsupported cases. Every PDF
source hash is checked unchanged. Separate native suites cover import,
expanded mappings, merge, undo, and the extraction check on the target machine.

Final release evidence is recorded in `LOCAL_PDF_R126_VERIFICATION.json` after
native release checks. Physical workstation/display/printing acceptance remains
separate; the automated checks are not a substitute for the user's deferred
visual review.

## Standards

The reader implements the relevant object, stream, cross-reference and security
portions of [ISO 32000-1](https://opensource.adobe.com/dc-acrobat-sdk-docs/pdfstandards/PDF32000_2008.pdf),
[RFC 1950](https://www.rfc-editor.org/rfc/rfc1950) and
[RFC 1951](https://www.rfc-editor.org/rfc/rfc1951). It is deliberately not a
general PDF rendering engine.
