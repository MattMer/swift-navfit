# Current-state review — r98, 10 October 2026

## Assessment and scope

r98 is a useful development baseline with substantial report/group/review functionality. The next investment should reduce unnecessary work, harden failure paths and close interoperability acceptance gaps. Adding another general workbench would increase complexity without addressing the strongest findings.

Reviewed current source, the r98 deployment verification and release scope. Used Access COM on a disposable copy of the synthetic deployment demo to measure repeated group navigation. No computer use, original-workspace changes or deployment modifications. The historical comparison save error is user-confirmed resolved; this review does not reopen that finding.

The baseline verification records 76 normalized source-module matches, native blank/demo startup, comparison save/approval/retry checks, queued-cell checks, 71 RUAD assertions, 354 authored UI/navigation assertions, 507 NAVFIT adapter assertions and 873 group export assertions. These are useful behavioral checks, not physical display, printer, screen-reader or complete interoperability acceptance.

## Ranked improvements

### 1. Harden queued-edit failure and close behavior

**Source-confirmed risk, not an observed new failure of normal saves.** `modUXTraitGrid.UXGridDrain` moves the pending queue into a local object and clears the global queue. After a failed cell it reloads the grid, and later queued cells are not replayed. `UXGridUnload` calls the drain but ignores its Boolean result, detaches the recordset and closes the cache; the generated form unload event does not cancel closure based on that result.

Preserve uncommitted cells after a failure, identify which edits saved, retain failed/pending values for retry or explicit discard, and prevent silent cache destruction on failed close. Flush or guard queued edits before contributor changes so attribution cannot change during delayed saving. Do not reintroduce prompts for ordinary successful saves.

Acceptance: inject one failure into a queue containing multiple reports/cells, including close and contributor-switch journeys. Already committed revisions remain correct; later edits stay recoverable; retry does not duplicate revisions; deliberate discard remains available. Existing stale and local-approval guards stay intact.

### 2. Stop rebuilding persistent group snapshots during routine navigation and cell saving

**Measured on the deployment demo.** Opening and closing one three-report group three times, with no edits, created three GroupSnapshot rows, nine GroupSnapshotMember rows, three ComparisonSet rows and nine ComparisonMember rows: 24 persistent rows. Opens took 853, 971 and 893 milliseconds on this machine. Evidence: `REVIEW_R98_NAVIGATION_EVIDENCE.json`. This is a small-fixture measurement, not a scale benchmark.

`UXOpenComparison` always captures a new snapshot/set when opening the view. `UXGridEdit` captures another complete snapshot/set for each changed cell. Each edit therefore adds approximately two roster-sized sets of member rows, in addition to its legitimate report revision. `UXGridRefreshAverages` also rewrites every cached member's ITA after each saved cell.

Separate the live Members view from durable meeting/comparison history. Reuse an unchanged saved group baseline or use a disposable live cache, and create durable snapshots when a history-bearing operation requires them. Preserve existing historical snapshots and proposal baselines; do not delete them casually. Update the changed row and group totals incrementally, with a full recomputation after roster changes or recovery.

Acceptance: simple navigation adds no durable history; editing costs do not grow by copying the entire roster; stale proposals still fail correctly. Measure 10/50/100/250-member groups, repeated opens and 100 consecutive edits, including file growth and lock duration.

### 3. Make editor calculation and live validation dependent on actual changes

**Confirmed code behavior; scale impact needs measurement.** `UXLiveTyped` validates on each typing event, and `UXLiveTimer` validates again each second. `UXRefreshEditor` requeries the group selector and walks saved group revisions with seven trait lookups per report, even for unrelated edits. `CheckpointEditor` compares against the saved baseline, so unchanged unsaved edits can be written again every 30 seconds; it refreshes Home when Home remains loaded.

Debounce typing validation briefly, validate immediately on field exit/save/review, and skip timer work when relevant values did not change. Cache saved group aggregates by group/revision stamp while keeping pending-editor results separate. Refresh membership only after membership changes. Fingerprint the last recovery checkpoint and skip identical writes; invalidate caches on revisions, roster changes and restored data.

Acceptance: idle editors do not rerun full validation or rewrite identical checkpoints; narrative typing does not recalculate saved group traits; field errors remain responsive and save/review always checks current values. Keep pending/saved averages and checkpoints/revisions visibly distinct.

Adaptive layout already caches applied width/height in `modUXViewport` and scopes context geometry to the active workspace. Keep that behavior. The evidence does not support replacing responsive forms with fixed-size forms as the next performance fix.

### 4. Finish the actual NAVFIT export/return workflow

**Confirmed missing capability.** `NAVFITPreviewReturned` explicitly rejects group export baselines. Existing report/group export adapter tests are not native round-trip acceptance. The controller/drawing harness establishes only partial proof.

Implement returned-group reconciliation with stable identities, whole-group before/current/returned preview, explicit conflict choices, native-only provenance retention and atomic apply. Add an export ledger showing baseline, exported revision, destination and return state; help users preserve the paired baseline without having to understand internal files. Prove Swift-generated EVAL/CHIEFEVAL/FITREP exports and returns in NAVFIT98A, including divergent local edits and approvals.

### 5. Finish comments-on-performance fidelity

**Known acceptance gap.** Establish type/pitch-specific dimensions and locked font behavior from NAVFIT98A's actual print branches. Provide a faithful measured preview and overflow warnings without truncating the user's text. Access textbox wrapping alone cannot certify native printed fit. Separate offscreen rendering evidence from physical printer-driver/output verification.

### 6. Make deployment updates and diagnostics trustworthy

**Confirmed documentation drift.** In-app Help still identifies version 0.23.0-preview/schema 21 while the app is 0.25.0-dev/schema 25. Help/support also contain independently hardcoded mapping counts. Generate version/schema/count text from constants and mapping metadata; distinguish supported features from acceptance status.

Provide an environment check for Access/ACE bitness and supported PDF extraction dependencies, with an actionable result. Verify schema-20-through-25 transfer on exact blank artifacts and histories, test restore rather than only backup creation, and retain a matched rollback copy. Consolidate duplicated historical state notes into a current capability/acceptance matrix. The current package is a development baseline, not verified deployment migration readiness.

### 7. Improve repeat RUAD workflows

**Useful expansion of the completed import foundation.** Offer suggestions from previously confirmed source/member bindings, with explicit review when identifiers change or collide. Add changed-only preview, missing-from-latest-roster reconciliation and journaled batch undo with later-edit guards. Do not infer identity from name or billet number alone, auto-delete missing people or overwrite member history.

### 8. Reduce field-definition and transaction maintenance risk

79 canonical fields are repeated across recovery arrays, form mappings, schema, import/export maps and tests; recovery loops hardcode 0 To 78. The Block 28 change illustrates how an addition can leave old counts and guidance behind. Generate aligned field/control metadata and conformance tests from a single registry, keeping official type-specific block labels separately verified.

Standardize DAO ownership, transaction ownership and failure cleanup without rewriting working save code wholesale. Add injected failures at revision creation/linking, imports, review reopening and UI refresh. Keep original error number/stage before cleanup so secondary cleanup failures cannot replace the useful diagnostic. Use a small diagnostics service with durations/counts, avoiding narrative/SSN logging.

### 9. Add leadership-focused workflow visibility

Recommended additions after the above foundations:

- A ready-for-signature checklist showing group eligibility, current approvals/routes, unresolved comments, missing information, stale reviews and export freshness. It summarizes supported checks; it is not automatic Navy certification.
- A member evaluation timeline showing prior/current report periods, ITA and recommendation changes, with gaps/overlaps flagged for review.
- Group progress and workload views with assignment, due date, blocker and next action. Build on existing My Work and lifecycle states.
- A submission/return tracker, separate from local approval and official signatures.
- An exception/decision log linked to the finding and saved revision, keeping leadership judgment attributable.

Do not introduce network synchronization, authentication or a simultaneous-user architecture implicitly. Evaluate a split frontend/backend only if that deployment requirement is explicitly adopted; separate workspace copies still do not synchronize.

## Database maintenance and measurement

Replace per-row VBA/domain lookups in Reports with joined/aggregated queries where semantics allow it. Measure before adding indexes: foreign keys and existing composite indexes already cover many paths, and extra indexes increase write work. Use the Access Performance Analyzer and inspect hot query filters/orderings rather than adding indexes to every field.

Add database-size/history-growth diagnostics and a deliberate backup-first compact/repair operation requiring exclusive access. Compacting reclaims wasted storage; it does not remove legitimate duplicate history rows. Access's documented file limit is 2 GB minus system-object space; this baseline is far below that limit, so this is preventive maintenance, not a current capacity alarm.

2. Live Members view and snapshot lifecycle optimization, with scale/file-growth measurement.
3. Change-driven editor validation, aggregates and checkpoints.
4. Returned-group reconciliation plus native round-trip proof.
5. Narrative rendering/overflow, then physical UX/accessibility and deployment acceptance.

Fix stale version/help text alongside the next build. r98 remains unchanged as the baseline; this review does not publish a new deployment.
