# Swift NAVFIT roadmap

Updated 21 October 2026. Desktop Microsoft Access is the supported host; free Runtime support is not required. [Current state](CURRENT_STATE.md) identifies verified artifacts and their evidence. The verified baseline is r127 / 0.27.0-dev, schema 27.

## Completed foundations

- Report drafting, saved revisions, recovery, fixed Front/Back pages and all seven Front Page traits.
- Explicit summary groups, defaults, previewed bulk changes, history and undo; reporting senior directory and completion accounting.
- Contextual help, guarded navigation, My Work, embedded report notes/replies, independent local review steps, validation views and trait calculations.
- Reviewed duplicate Sailor merging, retained original profiles and guarded undo. Folder permissions remain the accepted identifier-storage protection.
- Table-level Swift workspace transfer with exact database-engine verification, transaction rollback and retained-schema compatibility.
- Blank and synthetic Demo distributions, local backups and a procedure-based user guide.
- Local extraction from supported May 2025 fillable NAVPERS PDFs without Acrobat; official-form PDF output remains planned.

## Remaining priorities

The [current priority backlog](PRIORITY_BACKLOG.md), updated from the user's 21 October review, is the authoritative implementation queue. It retains reported severity, acceptance criteria, dependencies, partial deliveries and existing release gates. Review counts are not represented as a fresh verified inventory.

1. **Critical:** select the active contributor at startup; correct historical/effective-dated validation; normalize completion/RSCA state; establish canonical field definitions and authoritative revisions; strengthen data types; and finish audit, conversation and UI consolidation.
2. **High:** local official-template PDF report output with unique group/Sailor filenames and NAVPERS 1610/1 Summary Letters. Keep NAVFIT98A export. Current PDF extraction is not PDF output.
3. **Medium:** production ACCDE distribution (ideally signed), durable wizard state, joined/batched queries, actionable errors, validated UI contracts, runtime trait-definition tables, and actual accessibility acceptance. Continue publishing Blank/Demo ACCDB files for testing; free Runtime support remains out of scope.
4. **Low:** descriptive foreign-key names and unambiguous revision-ID field names.
