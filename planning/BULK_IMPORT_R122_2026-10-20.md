# Bulk Swift workspace import - r122c, 2026-10-20

Importing another Swift NAVFIT database is an upgrade transfer into a new blank release, not a merge. All source IDs, relationships, saved values, revision/review history, recovery, members and provenance remain intact.

## Implementation

- One explicit-column INSERT INTO ... SELECT per source table replaces individual insert/query/reopen/edit cycles. Target-only columns retain their new-version defaults.
- Report current revisions, revision parents, folder parents and comment threads are restored with bulk joined updates after every referenced row exists. Parent IDs need not precede child IDs.
- One TOP 1 emptiness guard replaces the two previous Count(*) destination scans. It excludes only first-run Workspace/UserProfile setup when the production upgrade entry point is used. Existing-data merge/reconciliation logic is not added.
- The migration engine owns one transaction, including setup replacement, compatibility conversions and the final source fingerprint check. A failed copy or relationship update restores setup and leaves no imported data. Temporary source-query definitions are prepared outside the data transaction and removed afterward; they never execute source VBA/macros.
- Error cleanup explicitly exits the active VBA handler before closing DAO handles and rolling back, preserving the original error and allowing a valid retry.
- Exact row/field verification and source fingerprint checks remain. These are now cheap relative to the eliminated per-row write work; the transfer still detects missing/extra rows, null changes, case changes and memo truncation.
- The progress log buffers its entries and limits expensive screen updates to four per second. Start and final success/failure paint immediately. Existing bounded-log retention remains. No DoEvents runs unrelated handlers within the transaction.

## Measured performance

Two alternating runs per engine, same machine and identical synthetic workspace containing 20,856 revision values, long Unicode notes, historical revisions and linked folders/comments:

| Measure | Seconds |
| --- | ---: |
| Previous per-record import, mean | 10.510 |
| Bulk-table import, mean | 0.659 |
| Actual bulk Apply screen, including progress | 0.821 |

The direct transfer is approximately 15.9 times faster in this test. Timings include full copied-field verification and source fingerprint checks; they exclude Access startup and copying the empty test template. The UI timing excludes file selection/preview. This is a synthetic local-disk benchmark, not a guarantee for every database or network folder.

The benchmark independently verifies long Unicode memo contents after reopen, next AutoNumber allocation, out-of-order folder/comment references and temporary-query removal. Fault injection verifies rollback for an oversized memo and a late invalid comment relationship, then a valid retry in the same target. Inputs and distribution hashes remain unchanged.
