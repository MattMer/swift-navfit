# Efficiency cleanup priorities 3-6 - r102 - 2026-10-10

App 0.25.0-dev; schema 25. Built from r101; prior workspaces remain untouched.

## 3. Target editor refreshes - completed

Field edits identify their field key. Narrative/name edits do not refresh the group selector or saved SGA; pending ITA refreshes for trait/observation changes. Group context is cached by report and selected group. Opening a report, successful report saves/archive changes, membership changes and group rename/lifecycle changes invalidate context; the next editor refresh updates it. Section changes can reuse context. Save refreshes saved SGA independently of pending ITA. Diagnostic refresh counters require no database reads.

## 4. Remove duplicate comparison work - completed

Removed frmUXComparison.lstTraits, its redundant per-member trait queries and event. The proposal selection/staging adapters now read the active editable grid row and its revision. Initial comparison load populates the proposal preview once, through UXRefreshComparisonPreview. Retained hidden trait/proposal adapter controls because the staging service still uses them; they are not unreferenced UI debris. Historical proposal/apply behavior remains available and tested.

Full build and incremental candidate helpers perform the cleanup after legacy layout helpers run, so later builds retain the removal. Old tests using the removed selector were adapted to the grid; historical proposal fixtures explicitly request Comparison mode.

## 5. Simplify group navigation - completed

Populated groups open Members directly from the directory without constructing frmMajorWorkbench. Members and Comparison tabs reuse their existing view. Other transitions resolve the group once, read its member count once, close with pending guards but without revealing a return destination, then open the target page directly. Defaults retains a hidden context host required by its existing adapter; Review/History retain the existing workbench page implementations. The host stays hidden during Members/Defaults transitions; screen painting resumes on success and failure. Back from live Members returns to Summary groups. Transaction and bulk-preview exit safeguards remain.

## 6. Event-driven idle work - completed

OnChange marks validation and recovery dirty. The existing one-second timer validates only when dirty (or calendar date changes). Field exit still performs immediate inline/live checks. Every 30 seconds, recovery is attempted only when dirty; success clears the flag, failure leaves it set for retry. New editor sessions reset timer/cache state. Both visible surface inputs and legacy buffer inputs notify typing changes. Active text is retained before field exit. An idle editor no longer scans all 79 fields each second.
